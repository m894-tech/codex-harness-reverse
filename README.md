# Codex (ChatGPT.app) — разбор харнеса

Спецификация агентского харнеса Codex, восстановленная из **скомпилированного бинаря** и конфигурации
на диске. Дополняет разбор Hermes Agent: это независимый дизайн, а не его вариант.

Объект: `/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`
(Rust, Mach-O arm64, 285 MB). ChatGPT.app `26.1117.31558`, Codex CLI `0.147.0`.

Метод: `strings -n 60` по бинарю (53 056 строк) — промпты лежат JSON-шаблонами в коде; плюс чтение
конфигурации с диска (`~/.codex/`): config, роли, хуки, правила, автоматизации, память, сессии.

## Что здесь главное

1. **Авторизация важнее подтверждения.** Разрешение живёт между ходами; подтверждение — только на
   необратимое и только после доведения работы до «можно ревьюить».
2. **Пять слоёв авторизации**: rules (prefix_rule, без модели) → sandbox_mode → approval_policy →
   ApprovalsReviewer → hooks. Только пятый слой использует LLM.
3. **Auto-review — LLM-классификатор** (`high`/`low`), чей вердикт виден клиенту как `GuardianAssessment`.
4. **Субагенты — треды** с каноническими именами; спавн только по явному запросу — «глубина/исследование»
   не считается разрешением.
5. **Память — конвейер** из 4 уровней с `applies_to: cwd=…` и ссылками на rollout'ы, а не плоский файл.
6. **Автоматизации** — cron внутри харнеса: iCalendar-rrule, модель и reasoning на задачу, уведомления
   только о падениях.

## Границы

Промпты извлечены из строк бинаря: возможны артефакты склейки в длинных литералах, а сами шаблоны — не
то, что уходит в API (рантайм подставляет переменные). Не покрыто: точные JSON-схемы тулов,
`skill_access.toml`, `requirements.toml`, `guardian_subagent`. Подробно — §22 спеки и `EVIDENCE.md`.
